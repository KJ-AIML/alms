# P0.4 — OpenAI Native Probe (offline)

## What this slice establishes

The first direct-SDK probe lane, implemented and verified entirely offline. It can
translate the P0.4 fixture subset into OpenAI Responses requests, execute through an
injectable client, capture raw native evidence, and emit a schema-valid probe response
over the subprocess protocol. No live call was made; all verification uses a narrow fake.

## Selected SDK and API surface

- SDK version: `openai==2.45.0` (latest on PyPI at selection; requires-python >=3.9),
  pinned in `probes/openai-native/pyproject.toml` and `uv.lock`.
- API surface: the **Responses API** (`client.responses.create`). Verified against the
  installed SDK, not the previous report: `input` / `instructions`, `max_output_tokens`,
  `temperature`, `text.format` (json_schema) for structured output, flattened `function`
  tools with `tool_choice`, and `stream=True`. `responses.parse` exists but is not used in
  P0.4 (we preserve raw text and let the harness interpret).
- Why Responses (not Chat Completions): it is the current official native interface and
  the surface the DevSpec's OpenAI native lane targets. Chat Completions would be a legacy
  comparison only, which the DevSpec does not require here.
- Streaming event types preserved verbatim: `response.created`,
  `response.output_text.delta` / `.done`, `response.function_call_arguments.delta` /
  `.done`, `response.refusal.delta`, `response.completed`, `error`, and unknown events.
- Exception surface available for the live path: `openai.APIError` /`APIStatusError` /
  `RateLimitError` / `NotFoundError` / `BadRequestError` / `AuthenticationError` / etc.

## Implemented fixture operations (P0.4 subset)

GEN-001, ROLE-001, STR-001, TOOL-001, STREAM-001, USAGE-001, ERROR-001 (base generation,
roles, structured output, single tool call, text streaming, usage, invalid-model error).
Parallel tools, cancellation, timeout, retry, embeddings, and multimodal remain in their
assigned later slices.

## Raw artifact layout

Per run under `runs/<id>/raw/` (gitignored): `openai_request.json`, and one of
`openai_response.json` / `openai_events.json` / `openai_error.json`, plus
`probe.stdout.txt` / `probe.stderr.txt`. The probe response manifest (probe-response v0)
references these by path and carries a redaction summary. Native semantics are not
flattened; raw stream events keep their native `type` and order.

## Offline fake strategy

A single narrow `MockResponsesClient` models only the Responses shapes P0.4 needs
(generation, structured, tools, refusal, no-usage, text/tool/unknown streams, and a
provider error). Tests inject it directly; the subprocess path uses it via
`controls.mock_mode = true`. There is no universal fake framework and no global network
monkeypatching; a `conftest` tripwire fails any accidental socket connection.

## Normalization

Normalization into audit vocabulary lives in the harness (`alms_audit.normalizers.openai`),
operating only on serialized raw JSON (no SDK import). It maps native event types to the
candidate vocabulary, preserves unknown events as `provider_extension`, keeps every event's
`raw_ref`, and produces a schema-valid normalized transcript.

## Live guardrails (fail-closed)

A real request is impossible unless every harness gate holds (`--live --confirm-live`,
valid budget, call cap, live-eligible fixture, selected lane, explicit model, credential
present, probe available) plus separate approval. Probe-level preflight returns
BLOCKED_CONFIGURATION (no model) or BLOCKED_CREDENTIAL (no credential) before any client is
built. BLOCKED_CREDENTIAL is a probe-level diagnostic reason; it maps to the schema result
status BLOCKED_CONFIGURATION (the vocabulary has no separate credential status).

## Known untested semantics (no live evidence yet)

Real model behavior for structured-output mode (native vs coerced), true tool-call IDs and
parallelism, real streaming event ordering and usage timing, and the real exception
taxonomy are all UNVERIFIED until a live run. The probe manifest marks model support as
`unverified_until_live`.

## Live test prerequisites (for a later, separately approved run)

Explicit approval; `OPENAI_API_KEY` present in the environment (never committed/logged); an
explicit cheap model id configured at run time; budget and call caps set; and the harness
run invoked with `--live --confirm-live`. Until then, no live evidence exists and none is
claimed.
