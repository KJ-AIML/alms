# P0.6C Cross-Lane Protocol Neutrality Audit and Hardening

Status: offline-only protocol review plus justified additive hardening. No live provider
request was made during P0.6C. No production ALMS code was modified. All work is additive and
backward-compatible under `research/runtime-audit/`.

Scope of evidence: the four implemented lanes `openai-native`, `langchain`, `anthropic-native`,
`gemini-native`, reviewed against their installed SDK/framework shapes, the current seven
evidence schemas, and the shared harness (`protocol.py`, `planner.py`, `runner.py`, the four
normalizers, `results.py`, `reporting/compare.py`).

Authority: P0.6C brief; DevSpec Sections 17, 18, 26, 29, 30, 31, 32, 43, 47, 48, 51, 75; Bible
ADR-002 (LOCKED, ALMS owns usage/error/structured-output semantics; "OpenAI-compatible types
rejected as vendor-shape coupling"), ADR-006 (LOCKED, conformance compares semantic invariants),
Section 52 (usage: "explicitly represent unknown values and provenance rather than silently
converting missing data to zero").

Severity system (DevSpec Section 18): F0 strategy-invalidating (challenges a LOCKED Bible
premise), F1 contract-changing (changes the shape or semantics of Draft ModelRuntime v0, KJ
review required), F2 capability-shaping (carry to Phase 1A), F3 implementation-note, F4
environmental. No finding here is F0: the Bible's usage/result schema surface is Draft/
Provisional, and every change below serves LOCKED principles rather than contradicting them.

## 1. Current shared protocol model

Two-record model (DevSpec Section 26). Every fixture-by-lane execution produces raw evidence
(what the runtime did, serialized as plain JSON with file paths) and a normalized interpretation
(mapped into a candidate audit vocabulary). Seven versioned schemas govern the artifacts:
`fixture`, `probe-request`, `probe-response`, `normalized-transcript`, `result`, `finding`,
`run-manifest`. All are namespaced `alms.dev/...-audit/...` and explicitly marked provisional
and NOT the ALMS runtime contract.

Flow: the harness `planner`/`runner` builds a `probe-request` (Probe Process Protocol v0,
`protocol.py`) and runs a probe subprocess per lane. The probe emits a `probe-response` raw run
manifest with paths to raw request/response artifacts. The harness `results.interpret` selects a
runtime-specific normalizer (`normalizers.select(runtime_layer)`), which produces a
`normalized-transcript` (every event carries a `raw_ref`), then builds a `result` record with an
audit `status` verdict and a usage block. `reporting/compare` produces a disclaimer-tagged,
implementation-shape-only cross-lane comparison. Three lane identifiers (runtime_layer /
provider / model) are kept independent and never collapsed (DevSpec Section 29).

Normalized event vocabulary (`normalized-transcript.schema.json`): `response_started`,
`text_delta`, `tool_call_started`, `tool_call_arguments_delta`, `tool_call_completed`,
`structured_output_completed`, `usage_updated`, `response_completed`, `cancelled`, `error`,
plus the two escape hatches `provider_extension` and `framework_extension`. Audit outcome
vocabulary (`result.status`): `PASS`, `PASS_WITH_EXTENSION`, `UNSUPPORTED_DECLARED`,
`UNSUPPORTED_OBSERVED`, `BLOCKED_CONFIGURATION`, `FAIL_INVARIANT`, `ERROR_RUNTIME`,
`INCONCLUSIVE`.

## 2. Provider-shape inventory

- `openai-native`: OpenAI Responses API. Container = `response.output` items
  (message / function_call); stream = `response.*` item lifecycle events; usage = nested
  `input_tokens_details.cached_tokens` / `output_tokens_details.reasoning_tokens`; terminal =
  `response.status` (completed / incomplete); convenience projection `output_text` exists but is
  not relied upon.
- `langchain`: framework layer over a provider. Container = `AIMessage` / `AIMessageChunk`;
  usage = framework-normalized `usage_metadata` (`input_token_details` / `output_token_details`,
  singular "token"); terminal = `response_metadata.finish_reason`; framework-synthesized stream
  chunks and framework metadata (`additional_kwargs`, `invalid_tool_calls`) exist.
- `anthropic-native`: Anthropic Messages API. Container = content blocks
  (text / tool_use / unknown); stream = message + content-block lifecycle (start / delta / stop)
  plus ping; usage = a two-field cache split `cache_creation_input_tokens` +
  `cache_read_input_tokens`, no total, no reasoning; terminal = `stop_reason`
  (end_turn / max_tokens / refusal / ...); structured = native `output_config.format`.
- `gemini-native`: Gemini Interactions API. Container = Interaction resource + chronological
  steps (user_input / model_output / function_call / thought); stream = interaction.created /
  step.start / step.delta / step.stop / interaction.completed; usage = totals
  `total_input_tokens` / `total_output_tokens` / `total_tokens` / `total_cached_tokens` /
  `total_thought_tokens`; terminal = Interaction `status` (completed / incomplete /
  requires_action / budget_exceeded / cancelled / failed); structured = native `response_format`
  (text.jsonSchema); `store=false` on every request; thought signatures are opaque.

The four shapes are genuinely unlike: item-based vs message/block-based vs step-based
containers; three distinct usage token vocabularies; four distinct terminal-state vocabularies.

## 3. Normalization invariant inventory

Verified present and honored in code:

- Raw-vs-normalized separation: every normalized event carries a required `raw_ref`
  (`normalized-transcript.schema.json`); a normalizer cannot silently delete semantics.
- Extension separation: native-but-unmapped semantics become `provider_extension`; framework
  transformations become `framework_extension`; the two are never conflated
  (`results._derive_status`, all four normalizers).
- Missing usage is null, never zero; `provenance="absent"` when no usage
  (`results._usage_block`; DevSpec Section 32; invariant `usage_not_fabricated`).
- `offline_mock` execution mode is never labelled `live` (`probe-response.schema.json`).
- Credential presence is booleans only; run manifest is `additionalProperties:false`
  (`run-manifest.schema.json`).
- Unsupported, blocked, failed, and error remain distinct result statuses (DevSpec Section 17).
- Structured presence with valid JSON alone is not native-structured proof; a native mechanism
  requires an explicit strategy/probe signal (`fixture.schema.json` comment;
  `compare._structured_mechanism`).

## 4. Bias findings (OpenAI-shaped assumptions)

One OpenAI-shaped assumption was found in the shared layer, the exact "vendor-shape coupling"
LOCKED ADR-002 rejects:

- N-02 (F1): `results._usage_block` read cache and reasoning tokens only via OpenAI's nested key
  paths (`input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens`). Every
  non-OpenAI normalizer therefore had to speak OpenAI's usage dialect to survive: the Gemini
  normalizer literally reshaped its native totals into OpenAI-nested keys (`gemini._map_usage`,
  pre-P0.6C). Anthropic (native `cache_*_input_tokens`) and LangChain (`input_token_details`)
  did not, so their cache/reasoning tokens were dropped to null in the result summary. This is
  the shared usage contract carrying an OpenAI vendor shape. Resolved (Section 14).

No other OpenAI-shape bias was found. Containers, tool semantics, streaming lifecycles, and
structured mechanisms were already provider-neutral via the extension events.

## 5. Data-loss findings

- N-02 (F1): as above, Anthropic cache-creation and cache-read tokens and LangChain
  framework cache/reasoning tokens were dropped from the result usage summary (they survived
  only in the raw artifact and the transcript `usage_updated` event, so the corpus never lost
  them, but the result contract did). The result schema also had a single `cached_input_tokens`
  and could not represent Anthropic's cache-creation-vs-cache-read split. Resolved (Section 14).

No lifecycle, tool, or event data-loss was found: all four normalizers preserve unmapped native
lifecycle as `provider_extension`/`framework_extension` with `raw_ref`, and unknown events are
never discarded (verified by `test_protocol_neutrality.py::test_unknown_events_are_never_discarded`).

## 6. False-equivalence findings

- N-01 (F1): `results._usage_block` hardcoded `provenance="reported"` for any present usage. The
  usage `provenance` enum (`reported`/`estimated`/`mixed`/`absent`) had no way to say "by whom",
  so LangChain framework-normalized `usage_metadata` and provider-reported OpenAI/Anthropic/
  Gemini usage were presented identically. `compare._fixture_view` surfaces exactly this field,
  so the comparison layer showed framework and provider usage as the same "reported" provenance.
  DevSpec Section 75 explicitly asks "Is usage provider-reported or framework-estimated?"; this
  distinction was unrepresentable. Resolved (Section 14).

No false equivalence was found in structured output (native json_schema vs
framework_function_calling are distinguished by `compare._structured_mechanism`), tool call IDs
(distinct provider IDs are never merged), or extension classification.

## 7. Fabricated-semantics findings

None. The normalizers were checked against the DevSpec Section 43 prohibitions and found clean;
this is now locked by negative tests (`test_protocol_neutrality.py`):

- No lane fabricates missing usage (missing stays null).
- LangChain never emits a provider-native event name (framework behavior stays
  `framework_extension`).
- Gemini thought steps are structural-only: a `provider_extension` carrying
  `thought_signature_present` (a boolean), never reasoning text.
- Distinct tool calls are not merged and no "parallel execution" flag is invented.
- Valid JSON alone is not treated as native-structured proof.

## 8. Extension handling review

Provider vs framework separation is correct and now regression-tested:

- `provider_extension`: OpenAI unknown item events, Anthropic content-block lifecycle + ping +
  refusal, Gemini step lifecycle + thought + requires_action + unknown native events.
- `framework_extension`: LangChain synthesized stream chunks and framework message metadata.

`results._derive_status` maps a `provider_extension` (or refusal) to `PASS_WITH_EXTENSION` with a
distinct note, and a `framework_extension` to `PASS_WITH_EXTENSION` with its own note; they are
never conflated. Confirmed by
`test_protocol_neutrality.py::test_langchain_framework_chunk_is_framework_extension_not_provider`
and the per-lane lifecycle tests.

## 9. Usage-neutrality review

After hardening, each normalizer's `extract_usage` returns a neutral, provider-shape-agnostic
usage summary carrying `input_tokens`, `output_tokens`, `total_tokens`, `cache_read_input_tokens`,
`cache_creation_input_tokens`, `reasoning_tokens`, and a `source` provenance tag. The native
usage object is still preserved verbatim in the transcript `usage_updated` event (that path was
untouched, so raw evidence is unchanged). `results._usage_block` no longer reads any
provider-specific key path.

- OpenAI: `source=provider_native`; cache_read from `input_tokens_details`, reasoning from
  `output_tokens_details`; no cache-creation (stays null).
- Anthropic: `source=provider_native`; cache_creation and cache_read both preserved; total and
  reasoning null (not reported, not fabricated).
- Gemini: `source=provider_native`; cache_read from `total_cached_tokens`; thought tokens mapped
  to `reasoning_tokens` (documented normalization).
- LangChain: `source=framework_native`; cache/reasoning from `input_token_details` /
  `output_token_details`.

Missing usage remains `provenance="absent"`, `source="unavailable"`, all tokens null. Locked by
`test_usage_provenance.py`.

## 10. Terminal-state review

Each lane has a distinct native terminal vocabulary (OpenAI `status`, Anthropic `stop_reason`,
Gemini Interaction `status`, LangChain `finish_reason`) with concepts that have no cross-provider
equivalent (Gemini `requires_action` / `budget_exceeded`, Anthropic `refusal`). Before hardening
these were preserved only inside the transcript and collapsed to `PASS`/`PASS_WITH_EXTENSION` at
the result level (N-03, F2). The audit `status` is the correct verdict axis, but the native
terminal state was not queryable at the result level.

Hardened: `result.observed_terminal_state` (optional) records `{native, category, source}`, read
back out of the transcript so it never contradicts the preserved evidence. Unknown native
terminal strings are kept verbatim with `category="unknown"` (no data loss). Locked by
`test_terminal_state.py`.

## 11. State and privacy review

No defect found; the model is strong. `store=false` on every Gemini request with no
`previous_interaction_id`; all lanes stateless in Phase 0; run manifest records credential
presence as booleans only and is `additionalProperties:false` so an accidental secret field
fails validation; Gemini thought signatures are kept as an opaque presence boolean, never
expanded; provider request/response IDs are preserved in raw for reproducibility without being
reused as conversation state. `timeout_or_cancellation_action` records the client-side action
only and does not claim the provider stopped.

## 12. Recommended schema changes

All additive and backward-compatible (no field renamed, no event type removed):

- `result.usage`: add `source` (usage provenance vocabulary), `cache_read_input_tokens`,
  `cache_creation_input_tokens`; keep `cached_input_tokens` as a back-compat alias of cache_read.
- `result`: add optional `observed_terminal_state` (`native` / `category` / `source`).
- `probe-response`: add optional `provider_returned_model` (N-05).
- New `protocol-neutrality-matrix` schema for the machine-readable matrix.

## 13. Compatibility impact

- Backward compatible. Every added field is optional; `result.usage` has no
  `additionalProperties:false`, so existing readers and existing committed evidence remain valid.
- `cached_input_tokens` is retained (now an alias of `cache_read_input_tokens`), so existing
  readers keep working.
- The usage `provenance` enum is unchanged; `source` is a new orthogonal field, so no existing
  value changed meaning.
- Existing normalizer callers are unaffected: `extract_usage` feeds only the result summary; the
  transcript path uses the native usage object directly and was not touched.
- Two normalizer unit tests that asserted the old `extract_usage` return shape were updated to
  the neutral shape (behavioral improvement, not a contract break for evidence consumers).

## 15. Deferred changes

- N-05 (F3, accepted, deferred non-blocking): `provider_returned_model` is added to the schema as
  an optional field but is not yet populated by any probe (the Gemini lane already keeps the
  returned model on the raw Interaction; the others preserve it in raw). The requested model is
  recorded and the returned model is preserved in raw, so there is no data loss today. The
  deferred model-identity work is NOT simply "let every lane populate a bare provider-returned
  model string." It must distinguish four facts:
    - `requested_model` — the configured/requested id (DevSpec Section 29 "configured model id").
    - `observed_returned_model` — the served model id actually observed for the run.
    - `observed_returned_model_source` — the provenance of that observation, drawn from
      `provider_native`, `framework_native`, `sdk_convenience`, `unavailable`, or
      `unverified_until_live`.
    - `raw_reference` — a pointer into the raw artifact that justifies the observed value.
  For a native lane, a model field read directly from the native provider response may be
  `provider_native`. For LangChain, a model name exposed through framework response metadata is
  framework-mediated and must NOT be automatically labelled `provider_native` — it is
  `framework_native` (or `unavailable`) until confirmed. This distinction, and the returned-model
  provenance in general, is `unverified_until_live` and is left for a probe-touching Phase 1A
  slice. The current `provider_returned_model` field comment already states that it asserts no
  provenance, so no committed schema or documentation makes a false model-identity claim.
- Streaming/usage/terminal behavior under a real provider stream is `unverified_until_live`
  (Section 16). No live change is made in P0.6C.
- No new provider or framework probes, no LiteLLM/PydanticAI lanes, no ModelRuntime
  implementation (out of scope; P0.7 not begun).

## 16. Live-validation requirements

The following can only be settled by a real provider call and are marked
`unverified_until_live` in the matrix:

- That the neutral usage summary correctly maps each provider's real usage block (especially
  Anthropic cache_creation/cache_read populated on a real cache hit, and Gemini
  total_thought_tokens on a real thinking model).
- That `observed_terminal_state` reflects real provider terminal states (real Gemini
  `requires_action`/`incomplete`/`budget_exceeded`, real Anthropic `refusal`/`max_tokens`).
- Real streaming event ordering, partial-vs-final usage, and synthesized terminal chunks.
- That `provider_returned_model` differs from the requested model on real dated snapshots.

No live provider request was made during P0.6C.
