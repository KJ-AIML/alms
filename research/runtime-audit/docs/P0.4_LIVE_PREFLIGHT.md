# P0.4 OpenAI Live Acceptance Preflight

Preflight only. No provider request was made. This records the bounded first-live plan and
the gaps that must be closed (in an execution-authorized session) before any live run.

## First-live configuration

`configs/first-live.override.toml` (separate from `audit.default.toml`; never weakens the
global defaults; contains no secret and no model):

- hard_cap_usd = 1.00, soft_cap_usd = 0.25, max_live_calls = 8
- max_output_tokens = 128, default_timeout_ms = 30000, retries = 0

Loading is fail-closed (a missing file raises). It is recorded in evidence by digest
(`config_digest` in the run manifest's `model_configuration`).

## Proposed model

`gpt-5.4-nano-2026-03-17` (exact snapshot, checked 2026-07-13): $0.20 / 1M input,
$1.25 / 1M output (cached-in $0.02 / 1M) — the current lowest-cost option. Sources: OpenAI pricing and model docs, and the GPT-5 developer
announcement. Required features are documented as supported on the Responses API: text
generation, structured output via JSON schema, function calling, streaming, usage
reporting. Per the audit's own rule, documented SDK/model support is NOT proof; native
structured-output strict-mode behavior and true tool-call semantics remain
`unverified_until_live`. The model must be supplied explicitly at run time; there is no
hidden default (the probe returns BLOCKED_CONFIGURATION when no model is configured).

Estimated upper-bound cost: 8 calls (the cap) x (~500 input + 128 output tokens) at
gpt-5.4-nano-2026-03-17 ~= $0.002, far below the $1.00 hard cap.

## Proposed first-live fixture set

GEN-001, ROLE-001, STR-001, TOOL-001, STREAM-001, USAGE-001 (6 base fixtures, one lane:
openai-native). No stress, parallel-tool, cancellation, retry, embedding, or multimodal
fixtures; only synthetic committed content; no business tools.

Planner-derived expected provider request count = 6 (one request per fixture; none of
these fixtures issue multiple requests). Cap 8 leaves headroom 2. Every fixture's
`max_output_tokens` is <= 128 (32/16/128/64/128/48), within the override.

## ERROR-001 decision

Excluded from the first live run. Its invalid-model-identifier semantics are exercised
offline via the probe's captured-error path and fake client. A live ERROR-001 would need a
separate justification (exact harmless request defect, why it cannot leak secrets, why it
creates negligible usage, which provider error semantic it tests, and why offline fault
injection is insufficient). Deferred.

## Defects found and fixed (narrow, in scope)

1. Live OpenAI client used the SDK default `max_retries=2`. Fixed: `build_live_client` now
   sets `max_retries=0` so the audit observes true single-attempt behavior (DevSpec
   Sections 64 and 80). Regression test added.
2. A rerun with the same run id would overwrite the immutable run manifest. Fixed:
   `write_run_manifest` refuses to overwrite an existing manifest (DevSpec Section 35).
   Regression test added.

## Gaps that block an actual live run (not defects; fail-closed)

These are not yet built and must be implemented in the execution session:

- Harness -> probe launch is not wired. `runner.run` passes the confirm/budget/call-cap
  gates and then raises `RunError("no runtime probes exist yet")`; it does not invoke the
  probe subprocess, collect raw artifacts, or run the normalizer. `subprocess_runner`,
  `protocol.build_probe_request`, and the OpenAI normalizer exist but are not connected.
- No CLI/config selection for a run: choosing the override config, an explicit model, a
  fixture subset, or a single lane is not exposed on `alms-audit run`.

Until these exist, a live run is impossible (the runner fail-closes), which is safe but
means execution cannot proceed from the current commit without further authorized work.

## Responsible source (functions)

- plan: `alms_audit/planner.py::build_plan`; `cli.py::cmd_plan`; used at `runner.py::run`.
- budget check: `alms_audit/budget.py::check_live_budget` / `check_call_cap` (runner.run).
- confirmation check: `runner.py::run` (`confirm_live`); `cli.py` run subparser flags.
- model configuration check: probe `__main__.py::run` (BLOCKED_CONFIGURATION when no model).
- credential-presence check: `environment.py::credential_presence` (booleans); probe
  `__main__.py::run` (BLOCKED_CREDENTIAL); the value is never read out or logged.
- probe launch: `subprocess_runner.py::run_probe` + `protocol.py::build_probe_request` +
  probe `__main__.py` (NOT yet invoked by `runner.run`).
- raw artifact storage: probe `serialize.py::write_capture`; harness `storage.py`.
- normalization: `alms_audit/normalizers/openai.py` (NOT yet invoked by the run flow).
