# P0.3 — Fixture Corpus v0

## What this slice establishes

The first language- and runtime-neutral audit fixture corpus that future probes will
execute. Fixtures define what behavior is tested, what inputs are controlled, what
semantic invariants are expected, what evidence must be collected, and what must not be
compared literally. No provider-specific execution, no live calls, no SDKs.

## Schema extension (`spec/fixture.schema.json`)

Added, as first-class validated fields (draft 2020-12, `additionalProperties: false`):

- `tier` — BASE / STRESS / OPTIONAL (DevSpec Section 56).
- `cost_class` — offline / live_core / live_stress.
- `allowed_outcomes` — array of result statuses; keeps unsupported distinct from failed.
- `evidence_requirements` — `{ raw, normalized }`; keeps raw evidence distinct from normalized interpretation.
- `intent` (optional), `execution.tool_choice`, and an optional `extension` escape hatch
  for provider-specific hints (never required to interpret a fixture).

## Semantic distinctions preserved

- Unsupported != Failed — `allowed_outcomes` keeps UNSUPPORTED_* / BLOCKED / FAIL_INVARIANT / ERROR_RUNTIME / INCONCLUSIVE distinct (STR-004, TOOL-004, STREAM-002, EMBED-001, MM-001 explicitly allow an unsupported outcome).
- Missing usage != Zero usage — USAGE-001/002 assert `usage_not_fabricated`, presence/provenance recorded.
- Schema-valid output != Native structured output — STR-001/002/004 record `observed_structured_mode`.
- Local cancellation != Confirmed provider-side termination — CANCEL-001 separates caller termination from provider-work evidence.
- Raw provider event != Normalized event — every fixture's `evidence_requirements.raw` differs from `.normalized`.
- Runtime retry != Provider retry — RETRY-001 (offline fault injection) records outbound attempts and hidden retries.
- Text stream != Structured-output stream — STREAM-001 vs STREAM-002.
- Single tool call != Parallel tool support — TOOL-001 vs TOOL-004.

Fixtures assert semantic invariants only; a test forbids exact-prose invariant keys. No
fixture contains secrets or a hardcoded provider model name (model ids are supplied at run
time; ERROR-001's invalid-model intent is carried as an `extension` hint, not a model literal).

## Corpus validation and listing (offline)

- `alms-audit validate` — each fixture validates against the schema, and duplicate IDs
  fail the whole corpus.
- `alms-audit list-fixtures [--feature F] [--tier T]` — deterministic, id-sorted, shows
  id / feature / tier / summary.
