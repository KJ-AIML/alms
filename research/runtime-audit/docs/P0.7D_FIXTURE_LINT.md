# P0.7D-fixture-lint — Offline Fixture Corpus Lint

Status: Tier-0 static validation. No live provider request. Completed in `5d87869`;
P0.7E closed the P0.3 explicit pending/manual-marker gap.

## What this slice establishes

`tools/fixture-lint/` layout pointer (DevSpec Section 21) with the single
implementation in the harness package so JSON Schema validation reuses existing
helpers. There is no second lint engine.

## Files

| Path | Role |
| --- | --- |
| `harness/src/alms_audit/fixture_lint.py` | Lint logic, evaluator registry, module CLI |
| `harness/src/alms_audit/cli.py` | `lint-fixtures` subcommand; `validate` calls fixture lint |
| `harness/tests/test_fixture_lint.py` | Corpus pass + negative cases |
| `tools/fixture-lint/README.md` | Layout pointer to harness entrypoints |
| `docs/P0.7D_FIXTURE_LINT.md` | This report |

## Checks (Tier 0 / P0.3)

1. Schema — each `fixtures/**/*.json` validates against `spec/fixture.schema.json`.
2. Duplicate IDs — fail the whole corpus.
3. `expected_invariants` — non-empty object.
4. Evaluator keys — each key is in `DEVSPEC_EVALUATORS`, `PENDING_EVALUATORS`, or
   `MANUAL_REVIEW` (explicit markers; no silent corpus-key auto-allow).
5. Provider-specific SDK method syntax — forbidden in common fixture fields.
6. Capability vocabulary — must match committed enum.
7. `cost_class=offline` requires `live_required=false`.
8. Deterministic issue ordering; non-zero exit on failure.

## Commands

From `harness/`:

```bash
uv sync --frozen
uv run ruff check .
uv run ruff format .
uv run pytest tests/test_fixture_lint.py -q
uv run alms-audit validate
uv run alms-audit lint-fixtures
uv run python -m alms_audit.fixture_lint
```

## Evaluator registry

`PENDING_EVALUATORS` lists corpus keys awaiting deterministic evaluators
(`evaluate_invariants` returns `mode=manual_review`, `detail=pending evaluator`).
`MANUAL_REVIEW` is empty for the current corpus. New keys must be registered before
landing.

## Why deferred-ideas still named this slice

`docs/P0.7D_DEFERRED_IDEAS.md` was written before `5d87869` landed and was not
updated when fixture-lint shipped. That is documentation drift, not a missing
implementation. P0.7E corrects the stale pointer.
