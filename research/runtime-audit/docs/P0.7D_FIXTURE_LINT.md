# P0.7D-fixture-lint — Offline Fixture Corpus Lint

Status: Tier-0 static validation only. No live provider request was made during this slice.

## What this slice establishes

`tools/fixture-lint/` layout (DevSpec Section 21) with the implementation in the harness
package so JSON Schema validation reuses existing helpers and no new runtime SDK
dependencies are introduced.

## Files

| Path | Role |
|---|---|
| `harness/src/alms_audit/fixture_lint.py` | Lint logic, evaluator registry, module CLI |
| `harness/src/alms_audit/cli.py` | `lint-fixtures` subcommand; `validate` calls fixture lint |
| `harness/tests/test_fixture_lint.py` | Corpus pass + negative cases |
| `tools/fixture-lint/README.md` | Layout pointer to harness entrypoints |

## Checks (Tier 0)

1. Schema — each `fixtures/**/*.json` validates against `spec/fixture.schema.json`.
2. Duplicate IDs — fail the whole corpus.
3. `expected_invariants` — must be a non-empty object (explicit check plus schema
   `minProperties`).
4. Evaluator keys — each key must be in the union of DevSpec Section 44 examples, keys
   used in the committed corpus, `PENDING_EVALUATORS`, or `MANUAL_REVIEW`.

## Commands

From `harness/`:

```bash
uv sync --frozen
uv run ruff check .
uv run ruff format .
uv run pytest tests/test_fixture_lint.py tests/test_cli.py -q
uv run alms-audit validate
uv run alms-audit lint-fixtures
uv run python -m alms_audit.fixture_lint
```

## Evaluator registry

`PENDING_EVALUATORS` and `MANUAL_REVIEW` are empty for the current corpus: every
non-DevSpec-example key is already present in committed fixtures and is collected into
the allowed union automatically. New keys must be registered in `fixture_lint.py` before
landing in isolation.

## Verification

See command block above. No provider SDK importable; no network access.
